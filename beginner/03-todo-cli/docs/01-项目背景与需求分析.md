## 设计思路

TaskService 的创建和状态切换对应用户需求；存储交给 Repository，避免 CLI 与 SQL 耦合。 本项目对任务创建允许相同标题，使用 ID 区分。持久化时间以 UTC 记录，截止日期按 YYYY-MM-DD 验证。

## 核心代码

下面摘自当前实际实现 [services.py](../src/taskflow/services.py)。

```python
"""任务业务操作。"""

import logging

from .models import Task
from .repository import TaskRepository

logger = logging.getLogger(__name__)


class TaskService:
    """状态操作保持幂等，日志只记录操作与 ID。"""

    def __init__(self, repository: TaskRepository) -> None:
        self.repository = repository

    def add(
        self,
        title: str,
        description: str = "",
        priority: str = "normal",
        due_date: str | None = None,
    ) -> Task:
        task = self.repository.create(title, description, priority, due_date)
        logger.info("创建任务 id=%s", task.id)
        return task

    def set_completed(self, task_id: int, completed: bool) -> Task:
        task = self.repository.get(task_id)
        status = "completed" if completed else "pending"
        if task.status == status:
            return task
        updated = self.repository.update(task_id, {"status": status})
        logger.info("修改状态 id=%s status=%s", task_id, status)
        return updated

    def search(self, keyword: str) -> list[Task]:
        return self.repository.list(keyword=keyword)
```

## 代码解释

add 将持久化交给仓储并记录日志。set_completed 在目标状态已满足时直接返回，否则更新状态。search 只组合业务入口。

## 运行方法

在项目目录执行编辑安装：

```bash
python -m pip install -e .
python -m taskflow --db demo.db add "学习 Python" --priority high
python -m taskflow --db demo.db add "学习 Python" --priority high
```

首次演练从新数据库开始，已有数据库时按实际新增返回的 ID 替换示例中的 1。正常查询打印 JSON；不存在任务打印错误到 stderr 并返回 1。帮助命令不创建数据库。

## 常见问题

- 找不到 taskflow 时检查当前解释器是否完成编辑安装。
- 日期错误时用完整的 YYYY-MM-DD，空标题和大于 200 字的标题也会被拒绝。
- 数据不一致时检查 --db 与 TASKFLOW_DB，确认调用的是同一数据库。
- CSV 按文本导入；导出内容保留原文，不对标题自动改写。

TaskService 的创建和状态切换对应用户需求；存储交给 Repository，避免 CLI 与 SQL 耦合。 修改时同步验证相关成功、异常和边界场景，再核对实际命令输出。
