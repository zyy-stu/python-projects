# 11 异常处理与日志

## 本章目标

ValidationError 与 TaskNotFound 是 TaskFlowError 的子类，CLI 在单个边界捕获业务异常。--verbose 开启 INFO，日志输出至 stderr。

## 前置知识

能够使用 Python 函数、包导入、异常和上下文管理器。先阅读[项目安装与命令](../README.md)，运行最小新增和查询，再学习本章。

## 设计思路

ValidationError 与 TaskNotFound 是 TaskFlowError 的子类，CLI 在单个边界捕获业务异常。--verbose 开启 INFO，日志输出至 stderr。 本项目对任务创建允许相同标题，使用 ID 区分。持久化时间以 UTC 记录，截止日期按 YYYY-MM-DD 验证。

## 核心代码

下面摘自当前实际实现 [exceptions.py](../src/taskflow/exceptions.py)。

```python
"""可向用户展示的业务错误。"""


class TaskFlowError(Exception):
    """统一业务异常。"""


class ValidationError(TaskFlowError):
    """输入未满足约束。"""


class TaskNotFound(TaskFlowError):
    """目标任务不存在。"""
```

## 代码解释

所有预期错误继承自 TaskFlowError，CLI 只在边界转为用户可读信息。未知编程错误仍应通过测试定位。

## 运行方法

在项目目录执行编辑安装：

```bash
python -m pip install -e .
python -m taskflow --db demo.db add "学习 Python" --priority high
python -m taskflow --db demo.db show 999
```

首次演练从新数据库开始，已有数据库时按实际新增返回的 ID 替换示例中的 1。正常查询打印 JSON；不存在任务打印错误到 stderr 并返回 1。帮助命令不创建数据库。

```bash
python -m pip install pytest==9.2.0 ruff==0.11.13
python -m pytest tests/test_cli.py -q
python -m pytest -q
```

核对[实际测试文件](../tests/test_cli.py)的断言。测试数据放在 tmp_path，CLI 测试通过 TASKFLOW_DB 指向临时文件。测试运行结果以关联提交的 CI 为准。

## 常见问题

- 找不到 taskflow 时检查当前解释器是否完成编辑安装。
- 日期错误时用完整的 YYYY-MM-DD，空标题和大于 200 字的标题也会被拒绝。
- 数据不一致时检查 --db 与 TASKFLOW_DB，确认调用的是同一数据库。
- CSV 按文本导入；导出内容保留原文，不对标题自动改写。

## 本章总结

ValidationError 与 TaskNotFound 是 TaskFlowError 的子类，CLI 在单个边界捕获业务异常。--verbose 开启 INFO，日志输出至 stderr。 修改时同步验证相关成功、异常和边界场景，再核对实际命令输出。
