## 设计思路

## 核心代码

下面摘自当前实际实现 [config.py](../src/taskflow/config.py)。

```python
"""用户环境配置。"""

import os
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class Config:
    """命令行覆盖环境变量，再使用默认路径。"""

    database: Path

    @classmethod
    def load(cls, database: str | None = None) -> "Config":
        selected = database or os.environ.get("TASKFLOW_DB")
        path = Path(selected).expanduser() if selected else Path.home() / ".taskflow/tasks.db"
        return cls(path.resolve())
```

## 代码解释

Config.load 读取命令行及环境变量，expanduser 和 resolve 形成绝对路径。测试显式传路径，避免触碰用户默认库。

## 运行方法

在项目目录执行编辑安装：

```bash
python -m pip install -e .
python -m taskflow --db demo.db add "学习 Python" --priority high
python -m taskflow --db demo.db show 1
```

首次演练从新数据库开始，已有数据库时按实际新增返回的 ID 替换示例中的 1。正常查询打印 JSON；不存在任务打印错误到 stderr 并返回 1。帮助命令不创建数据库。

## 测试方法

安装开发依赖后运行相关测试和完整测试：

```bash
python -m pip install pytest==9.2.0 ruff==0.11.13
python -m pytest tests/test_cli.py -q
python -m pytest -q
```

核对[实际测试文件](../tests/test_cli.py)的断言。测试数据放在 tmp_path，CLI 测试通过 TASKFLOW_DB 指向临时文件。测试运行结果以关联提交的 CI 为准。

## 常见问题

- 找不到 taskflow 时检查当前解释器是否完成编辑安装。
- 日期错误时用完整的 YYYY-MM-DD，空标题和大于 200 字的标题也会被拒绝。
- 数据不一致时检查 --db 与 TASKFLOW_DB，确认调用的是同一数据库。
- CSV 按文本导入；导出内容保留原文，不对标题自动改写。
