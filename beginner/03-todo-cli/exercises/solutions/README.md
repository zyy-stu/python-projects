# 分支实现与参考设计

1. **任务标签**：建立关联表并为标签去重。在独立分支先加失败测试，再实现 models、repository、database 的最小改动，最后按“一项任务可有多个标签并可按标签筛选”验收。

2. **任务分类**：先确定分类删除对任务的影响。在独立分支先加失败测试，再实现 models、repository 的最小改动，最后按“分类增删改及任务归类测试通过”验收。

3. **任务统计**：为零条任务定义结果。在独立分支先加失败测试，再实现 services、cli 的最小改动，最后按“输出待办数、完成数和优先级分布”验收。

4. **任务排序**：SQL 排序字段同样使用白名单。在独立分支先加失败测试，再实现 repository、cli 的最小改动，最后按“按优先级或截止日期稳定排序”验收。

5. **截止提醒**：测试传入日期，避免依赖当天。在独立分支先加失败测试，再实现 services、cli 的最小改动，最后按“按给定日期输出到期和过期任务”验收。

6. **JSON 导出**：复用临时文件写入思路。在独立分支先加失败测试，再实现 exporters 的最小改动，最后按“支持中文、空任务与原子替换”验收。

7. **批量删除**：先定义部分 ID 不存在时的行为。在独立分支先加失败测试，再实现 services、repository 的最小改动，最后按“一次事务内删除所有指定 ID”验收。

8. **任务导入**：定义 ID 冲突和重复数据策略。在独立分支先加失败测试，再实现 repository、cli 的最小改动，最后按“校验全部行后事务提交”验收。

涉及现有数据结构的练习需添加版本化迁移，验证旧数据库仍可读取。
